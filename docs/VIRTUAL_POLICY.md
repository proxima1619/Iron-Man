# 가상 설비 전용 승인 정책

## 바뀐 동작

초기 가상 상태(60°C, 실제·목표 펌프 속도 100%, 부하 1)를 관측한 뒤 60%·300초 요청은 냉각 효율 저하 시험의 한계 초과로 차단됩니다. 80%·300초 요청은 정상·효율 저하 시험을 통과하면 **담당자 승인 대기**가 됩니다. 승인 전에는 가상 상태가 바뀌지 않습니다.

`backend/gateway/policy.py`가 서버 규칙의 원본입니다. 정책 버전은 `virtual-cooling-policy-v2`, 대상 모델은 `cooling-demo-v3`입니다. 논문·문서·LLM 응답으로 이 규칙·온도 한계·실행 권한을 바꿀 수 없습니다.

## 승인 대기로 보내는 조건

| 항목 | 조건 |
|---|---|
| 적용 대상 | `cooling-demo-01`, `set_pump_speed`, 정확히 `DemoAdapter`인 가상 어댑터 |
| 모델 | 평가 결과와 현재 가상 상태 모두 `cooling-demo-v3` |
| 입력 | 합성 상태, ready, 유효 센서, 관측 후 0~60초 |
| 승인 범위 | 초기 온도 0~80°C, 부하 0~1.5, 실제·목표 속도 0~100%, 요청 속도 20~100% |
| 예측 구간 | 정확히 300초. 다른 구간은 보류, 20% 미만 속도는 규칙 위반 차단 |
| 필수 시험 | normal + degraded_cooling. 에이전트가 생략해도 서버가 효율 저하 시험 추가 |
| 계산 | completed, mock=false, model_calculation, 서버 한계 80°C와 일치 |
| 온도 | 모든 시험에서 변경 전·변경 후 최고 온도 모두 80°C 이하 |
| 근거 | 아래 모의 근거 또는 검증된 팀 작성 문서 경로. 부족·실패·출처 불일치는 보류 |

모델 자체의 지원 범위가 정책의 승인 범위보다 넓을 수 있습니다. 계산 가능하다는 이유만으로 승인 가능해지지 않습니다. 변경 전 상태가 이미 한계를 넘는 개선·긴급 조치는 이 정책에서 승인하지 않습니다.

## 근거 모드

- **기본 fixture:** 지정 source ID·타입·원본 위치를 가진 팀 작성 모의 카드 1개만 허용합니다. 적용 조건 `unknown`은 가상 흐름 시연을 위한 명시적 예외이며 현실의 근거 충족으로 취급하지 않습니다. 보고서의 evidence.mock=true와 한계를 계속 표시합니다. 빈 근거나 다른 fixture는 보류합니다.
- **live:** completed, 모든 카드 applicable, 확인된 조건이 있고 미확인 조건이 없어야 합니다. 팀 작성 `data/sources/cooling-demo.json`의 메타데이터·실제 인용문과 대조합니다. 문서 묶음 SHA256은 정책 파일에 고정돼 있어 파일을 바꿔도 승인 범위가 확장되지 않습니다. 실제 논문·매뉴얼·다른 문서로의 확장은 별도 정책 검토 대상입니다.
- 실제 외부 LLM API 호출은 이번 검증에서 실행하지 않았습니다. live 정책 검사는 LLM 전송을 대체한 테스트 응답으로 검증합니다. 문서 검증·물리 계산·승인 서버는 실제 코드를 사용합니다.

## 승인과 적용 시 재검사

보고서에 `execution_scope=virtual`을 포함합니다. 과거 보고서에 이 필드가 없으면 `unconfigured`로 해석하며 새 정책의 승인 대상으로 사용하지 않습니다. 새 평가가 필요합니다. 모델·정책이 바뀌어도 재검증합니다. 기존 DB의 보고서·이력을 덮어쓰지 않습니다.

승인 API는 승인자 역할, 최신 보고서 digest, 요청 revision·명령, 현재 상태 digest, 보고서 원래 관측 시각, 모델·정책·어댑터·근거·계산 조건을 확인합니다. 실패하면 409와 재검증 필요 상태로 전환합니다. 관측 갱신만으로 오래된 보고서의 유효 시간을 늘리지 않습니다.

적용 API는 같은 조건과 승인 만료 시각을 다시 확인합니다. 승인 후 가상 시간 진행·부하 변경·초기화로 상태가 달라지면 적용하지 않습니다. 완료된 동일 실행을 재요청하면 이전 영수증을 반환하며 중복 적용하지 않습니다.

## 데모 진행

1. 승인자 토큰으로 **가상 설비 초기화**. 초기화는 요청·보고서·이력을 지우지 않습니다.
2. 요청 토큰으로 **60%** 요청 → 자동 결과 갱신 → 차단·효율 저하 시험 확인.
3. **80%** 새 요청 → 승인 대기 → 적용 전 가상 상태가 유지되는지 확인.
4. 승인자 토큰으로 **승인 → 가상 설비에 적용** → 목표 속도 80% 확인.
5. **가상 시간 10초 진행** → 실제 속도와 온도 변화를 확인.
6. 초기화 후 다시 80% 요청·승인 → 적용 전에 가상 시간 진행 → 적용 시 409·재검증 필요 확인.

검토 중 관측 후 60초가 지나면 보류됩니다. 관측 갱신 뒤 **새로 평가**해야 합니다. 시연 직전에 초기화하거나 관측을 갱신하고 진행하세요.

가상 적용은 **목표 속도 설정**입니다. 실제 속도와 온도는 수동 가상 시간 진행 때 계산됩니다. 300초는 예측 구간이며 설정의 자동 만료 시간이 아닙니다. 실제 설비의 지속 안전성, 자동 정지·복구·롤백, 현장 적합성을 보장하지 않습니다.

```bash
.venv/bin/pytest -q
cd frontend
npm run generate:api
npm run build
```

GitHub Actions의 Compose·HTTPS·Chromium 검사는 가상 승인·적용·온도/속도 변화·상태 변경 후 적용 거절을 실제 모듈로 확인합니다. 근거 부족·계산 실패·잘못된 한계·가짜 계산·다른 어댑터·잘못된 예측 구간·오래된 보고서는 백엔드 테스트로 보류/거절을 확인합니다. AWS 자원은 생성하지 않습니다.
