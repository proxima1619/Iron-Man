# 로컬 TEP 참조 데이터 확인

2026-10-09. 추가된 경로: `archive/TEP_data/`.

## 분류

동봉 `readme.txt`는 Fortran 기반 TEP 개루프/폐루프 시뮬레이션 코드와 정상·고장 학습/시험 데이터를 설명한다. 따라서 현재 분류는 **시뮬레이션 참조 데이터**이며 현장 실측·실제 설비 검증 자료로 등록하지 않는다. MIT Braatz 그룹의 [소프트웨어 안내](https://web.mit.edu/braatzgroup/links.html)도 TEP 자료를 simulation data로 소개한다. 사용자가 업로드한 파일의 실제 다운로드 URL·원본 버전은 아직 확인 중이며 공식 배포 파일과 바이트 일치를 확인한 상태는 아니다.

동봉 README에는 University of Illinois 1998–2002 저작권, 사용·복제·수정·배포 허가와 고지 유지·보증 부인·명칭 사용 조건이 있다. 코드/문서 고지는 원본에 남겨둔다. 데이터 파일에 대한 정확한 라이선스 적용 범위와 원배포 출처는 추가 확인하며 이번 확인에서 원본 자료를 GitHub에 재배포하지 않았다.

## 파일 검사 결과

44개 `.dat`, 정규화 후 총 **31,700개 관측**, 관측마다 52개 값. 모든 파일을 읽었으며 NaN·무한대는 0개다. 구조 검사 통과는 물리 정확도나 출처 검증 완료를 뜻하지 않는다.

| 파일 | 실제 저장 형태 | 읽을 때 처리 |
|---|---|---|
| `d00.dat` | 52행 × 500열 | 전치하여 500행 × 52열로 읽기 |
| `d01.dat`..`d21.dat` | 각각 480행 × 52열 | 행마다 관측 |
| `d00_te.dat`..`d21_te.dat` | 각각 960행 × 52열 | 행마다 관측 |

README의 학습 파일 480행 설명은 실제 `d00.dat`의 500개 표본 및 전치 형태와 다르다. 파일을 일괄 480행으로 자르거나 잘못된 방향으로 읽지 않는다. 파일별 원본 SHA-256·관측 수·유한값 검사·선택 변수 통계는 로컬 `data/tep-local-data-audit.json`에 보존했다. 원본 파일은 변경하지 않았다.

동봉 변수 순서는 `XMEAS(1..41), XMV(1..11)`이다. XMV(12)와 전체 50 내부 상태는 이 관측 배열에 없다. 냉각수 입력 XMV10/11은 1부터 세는 **51/52번째 열**이며 Python 인덱스는 50/51이다. 단위는 동봉 모델과 현재 변수 사전을 대조해 사용해야 하며 실제 펌프 RPM으로 해석하지 않는다.

전치한 정상 학습 `d00.dat`의 확인 예:

| 변수 | 최소 | 최대 | 평균 |
|---|---:|---:|---:|
| XMEAS7 반응기 압력 (kPa gauge) | 2690.5 | 2715.8 | 2705.3974 |
| XMEAS9 반응기 온도 (°C) | 120.35 | 120.45 | 120.39944 |
| XMV10 반응기 냉각수 설정 (percent_full_scale) | 39.51 | 42.641 | 41.09475 |
| XMV11 응축기 냉각수 설정 (percent_full_scale) | 14.009 | 23.144 | 18.215882 |

이 최소·최대는 해당 시뮬레이션 기록의 통계이며 정상 운전 또는 안전 허용 한계로 등록하지 않는다.

## 현재 실행 모델과 비교할 때 필요한 확인

- `temain_mod.f.txt`는 plant-wide 폐루프 제어를 포함한다. 원본 코드 설명/출력 루프는 180초 기록 간격이며 적분은 1초이다. 각 `.dat`에 timestamp가 없어 파일별 실제 시작 시점·간격·전처리를 별도 확인해야 한다. 확인되지 않은 시각을 실제 계측 시각으로 생성하지 않는다.
- 동봉 코드에는 3/360/900초 주기의 여러 제어 루프와 8시간 이후 외란 적용 설정이 있다. 현재 코드 한 벌의 외란 설정을 모든 `d01..21`의 실제 생성 설정으로 간주하지 않는다.
- `teprob.f.txt`의 현재 seed는 `4651207995`이고 파일별 seed 후보가 주석으로 남아 있다. 주석의 대응이 실제 파일 생성 기록과 일치하는지는 아직 검증하지 않았다.
- 현재 Iron-Man NIST 경로는 원본 기본 상태·시드 1431655765·제어기 없음·0.1초 적분·기본 10초 관측·최대 1800초 시험이다. 폐루프 기록과 초기 상태·시드·제어·시간축이 일치하지 않는다.
- 관측 52개를 내부 50 상태의 체크포인트로 사용하지 않는다. 대응 조건 없이 현재 모델과 행 순서만 맞춘 RMSE를 정확도나 현장 오차로 표시하지 않는다.

현재 정상/고장 참조 기록의 로더·API·데모 화면을 연결했다. 출처 확인 후 동일 제어기·초기 상태·시드·입력 이력을 맞춘 참조 재현 비교는 후속 작업이다. 실제 설비 오차·현장 적용성 검증은 별도 실측 자료가 확인될 때 진행한다. **현재 실측 검증은 미완료, TEP 승인 정책은 hold 상태를 유지한다.**

## 데모에서 사용하는 방법

기존 백엔드·프런트를 실행한다. **데모 체험** 화면(`/#demo`)의 **TEP 참조 데이터 · 정상/고장 기록 탐색**을 펼치거나, **검토 콘솔**(`/#review`)에서 역할 토큰을 입력해 연결하고 TEP 모델을 선택한 뒤 같은 항목을 펼친다. 기본 정상 시험 기록은 `d00_te.dat`다. 정상/Fault 1..21의 학습·시험 기록과 52개 변수를 선택하고 표본 번호 그래프·최소/최대/평균·전체 값을 확인할 수 있다. JSON 저장에는 선택 변수 전체 값, 원본 해시, 변수 순서·단위, 확인되지 않은 생성 설정도 포함한다. 통계는 관측 범위이며 정상/안전 허용 범위가 아니다. Fault 번호의 물리 의미나 시작 위치는 추정해서 표시하지 않는다. 데모 체험의 기존 합성 탱크 승인 예시는 별도로 유지하며 TEP 참조 데이터로 판정하지 않는다.

변경 요청 생성·평가는 이전처럼 **외부 NIST 엔진**에서 같은 초기 상태로 기준 입력·변경 입력을 계산한다. 참조 기록을 재생하여 새 명령의 결과처럼 보여주거나 첫 행을 완전한 초기 상태로 사용하지 않는다. 참조 조회는 요청·보고서·SQLite 설비 상태를 수정하지 않는다. 참조 기록은 인쇄 승인 보고서에서 제외하며 내려받는 JSON에도 `record_kind=prerecorded_reference`, `data_origin=simulation`, `used_for_approval=false`, 실측 검증 미완료를 보존한다.

### 로컬 경로와 API

기본 `archive/TEP_data`를 그대로 두면 읽을 수 있다. 설치 패키지·다른 경로에서는 다음과 같이 백엔드 실행 전에 절대 경로를 설정한다. `.env.example`은 안내이며 자동 로드되지 않는다.

```powershell
$env:IRON_MAN_TEP_REFERENCE_DIR='C:\Users\renbn\Documents\Codex\Iron-Man\archive\TEP_data'
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

프런트는 `frontend`에서 `npm run dev`로 실행한다. 역할 토큰은 백엔드의 기존 설정을 따른다. 직접 조회/저장 예:

```powershell
$headers = @{'X-Iron-Man-Token'='local-operator'}
Invoke-RestMethod 'http://127.0.0.1:8000/tep/reference/catalog' -Headers $headers
$result = Invoke-RestMethod 'http://127.0.0.1:8000/tep/reference/series/d00.dat?variable=XMV10' -Headers $headers
$result | ConvertTo-Json -Depth 12 | Set-Content -Encoding utf8 data/tep-reference-XMV10.json
```

파일 이름은 해시 프로필에 있는 44개로 제한한다. XMV12는 기록에 없으므로 조회할 수 없다. 전체 52개 열을 검사한 뒤 선택 변수만 반환한다. `d00.dat` 전치, 관측 수, NaN/무한대, 단위와 원본/설명 파일의 SHA-256을 검사한다. 자료 없음·손상·프로필 불일치는 HTTP 503과 오류 코드만 반환하고 부분 성공 시계열을 반환하지 않는다. 미지원 파일은 404, 미지원 변수는 422, 인증 없음은 401이다. 프로필의 해시는 **현재 로컬 업로드의 식별자**이며 공식 원배포 자료와 바이트 일치를 증명하지 않는다. 파일이 변경되면 재검토 후 프로필을 갱신해야 한다.

### 배포 담당 1번에게 넘길 사항

원본 데이터는 저장소나 wheel에 포함하지 않는다. 로컬 경로는 API 프로세스가 직접 읽으므로 별도 프로그램이나 MATLAB 라이선스는 필요하지 않다. 배포 시 데이터/허가 고지를 서버에 별도로 전달하고 API 컨테이너에 **읽기 전용**으로 마운트한 경로를 `IRON_MAN_TEP_REFERENCE_DIR`에 지정해야 한다. `readme.txt`, `teprob.f.txt`, `temain.f.txt`, `temain_mod.f.txt`도 해시/변수 정의 검사에 필요하다. Dockerfile·Compose·CI 최종 통합은 1번 담당이며 이번 작업에서 컨테이너 배포·라이선스 적용 범위 확인을 완료했다고 표시하지 않는다. 참조 경로가 없으면 참조 탐색에만 실패 메시지를 표시하고 외부 TEP 실행은 계속 지원한다.

### 검증

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
$env:IRON_MAN_TEST_TEP_REFERENCE='1'
.\.venv\Scripts\python.exe -m pytest tests/test_tep_reference.py -q
```

17개 참조 테스트 통과: 실제 44개 파일·31,700개 관측의 전체 열 유한값 검사와 반복 읽기 일치, 전치/냉각수 열/단위 매핑, 미지원 변수·누락·손상·해시 불일치·불명 단위의 실패, API 인증과 가상 설비 상태 미변경을 확인했다. 작은 합성 배열은 파서/HTTP 검사용이며 물리 모델 검증용 데이터가 아니다. 외부 TEP 실행 검증은 [TEP_INTEGRATION.md](TEP_INTEGRATION.md)의 별도 시험을 따른다. 현재 단계는 기록 구조와 연동 재현성 확인이며 실측 정확도 또는 실제 설비 적용성 검증은 미완료다.

최신 팀원 데모·근거 변경 병합 후 전체 307개 테스트·TypeScript 검사·프런트 빌드 통과. 로컬 브라우저 `/#demo`에서 정상 시험 960개, 전치 정상 학습 500개 및 Fault 1 시험 960개로 전환하고 XMV10의 단위·통계·그래프와 JSON 저장을 확인했다. 저장 JSON에도 시뮬레이션 분류·원본 해시·미확인 설정이 보존되며 브라우저 콘솔 오류는 없었다. Docker에서 참조 데이터 마운트를 시험한 것은 아니다.
