# 현재 구현과 팀원 인계

## 1번

`Gateway`는 요청·검토·판단·실행을 조율합니다. 단일 프로세스 `RLock`으로 승인과 실행을 직렬화하고, report digest와 command/state/model/policy를 확인합니다. 요청별 중복 실행은 이전 결과를 반환합니다.

다음 작업: 사용자별 인증, 서비스 인터페이스 분리, 비동기 작업 상태, 오류 상세 내부 로깅, 실행 결과 조회·재조정. 현재 모듈 호출은 lock 안에서 동기식이므로 느린 실제 LLM을 연결하기 전에 작업 큐/작업 revision 검사를 추가하세요. 외부 장비용 보안 경계로 사용하지 마세요.

## 2번

`simulate()`는 합성 초기 상태와 고정 계수를 사용하는 단순 열수지 모델로 변경되었습니다. 동일한 초기 상태에서 기존 속도와 요청 속도를 비교하고, 정상·효율 저하 조건의 최고 온도와 한계 초과 여부를 v1.0 계약으로 반환합니다. 내부적으로 온도 시계열을 계산하지만 현재 공통 API에는 포함되지 않습니다. 센서 불량과 모델 입력 범위 밖은 `out_of_domain`으로 반환하며 관문은 보류합니다. 계수와 한계는 현장 검증값이 아닌 데모 가정입니다. 자세한 식과 범위는 `docs/model_card.md`를 보세요.

`DemoAdapter`는 SQLite에 저장된 가상 상태만 바꾸며 센서 관측 시각도 호출 시각으로 생성합니다. 실제 센서 노후·물리 응답을 검증하지 않습니다. 실제 계측 연동은 별도 구현 대상입니다.

## 3번

`review_evidence()`는 팀 작성 fixture 카드와 degraded_cooling 시험을 반환합니다. 실제 원문·검색·LLM 호출·프롬프트 주입 검증이 없습니다. 출처 메타데이터, structured output 검증, 필수 적용 조건 누락 시 보류 계약을 추가하세요. 문서 내용에서 실행 권한을 얻지 않는 경계를 유지하세요.

## 4번

API 연결된 React 화면과 비교 표가 있습니다. 다음은 시계열 그래프, 근거 원문 열기, 입력 검증 UX, 오류/진행 표시 개선, 접근성, 발표 자료·영상입니다. 화면은 OpenAPI에서 자동 생성한 `api.generated.ts` 타입을 사용합니다. 계약 변경 후 `npm run generate:api`를 실행하세요.

## 이번 골격에서 제외한 것

실제 AI 모델, 진짜 논문/매뉴얼, 검증된 물리 모델, 실제 로그인, 배포 주소, PDF·영상, PLC, 자동 복구, 안전 인증. 개발 계획 문서의 P0 전체가 완료된 상태가 아닙니다.


## 1번 개발 1단계 — 공통 계약 v1.0

계산 결과·근거 카드·보고서·요청 응답을 명시적인 Pydantic 타입으로 정의했습니다. 모듈 경계에서 응답을 재검증하고, 근거 부족·범위 밖·필수 시험 누락·형식 오류는 보류합니다. 비모의 모듈 승인 정책은 아직 미구현이며 자동 승인 가능 상태로 전환하지 않습니다.

다음 1번 작업: 실제 LLM 호출이 전체 요청을 잠그지 않도록 평가 작업 상태와 revision 검사를 구현합니다. 현재 전체 잠금과 동기 호출은 남아 있습니다.


## 1번 개발 2단계 — SQLite 저장

`backend/gateway/storage.py`에 요청·보고서/승인 이력·가상 설비 상태·적용 영수증을 저장합니다. 기본 DB는 `data/ironman.sqlite3`, 배포 시 `IRON_MAN_DB_PATH`로 지정합니다. 데이터 파일은 Git에서 제외합니다.

API `/requests` 목록과 `/requests/{id}/history`를 추가했고 기존 API 형식은 유지했습니다. UI에서 저장된 요청을 다시 불러올 수 있습니다. 시작 시 미완료 검토는 보류, 미완료 실행은 결과 불명으로 복구합니다. 프로세스 잠금으로 동일 DB의 다중 서버를 거부합니다. 평가 작업 분리와 외부 배포는 아직 미구현입니다.
