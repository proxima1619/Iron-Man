# 현재 구현과 팀원 인계

## 최신 변경: TEP 외부 연동 v1

2026-10-09: NIST TEP 코어를 실제 C++ 프로세스로 실행하는 `backend/simulator/tep`를 추가했습니다. 소스 고정·라이선스 보존·명시적 빌드·기준/변경 독립 실행·시계열/단위/비교·실패 보류를 구현했습니다. 선택 근거, 원본 코어와 래퍼의 차이, 전체 실행 설정과 후속 데이터 요구는 [TEP_INTEGRATION.md](TEP_INTEGRATION.md)에 있습니다.

기존 `/requests`에 `tep-sim-01 / set_tep_cooling_water`를 추가했습니다. TEP 초기화 프로필과 `report.tep_simulation`을 SQLite/이력/비동기 평가에 보존합니다. UI 기본 모델은 TEP이며 시계열과 변수별 비교를 표시합니다. TEP의 `simulation/assessment/evidence`는 null입니다. 기존 탱크·근거 모듈을 TEP 검증으로 재사용하지 않습니다.

계산 성공은 `hold / TEP_POLICY_NOT_CONFIGURED`입니다. 승인·실행 거절 및 알림 미발송을 계약과 관문에서 강제합니다. 1번은 TEP 전용 정책, 3번은 TEP 운전 조건에 맞는 근거·반례, 4번은 해당 정책/검증 범위 표시를 후속 검토해야 합니다. 실측 데이터가 없어도 외부 연동은 진행했고, 실측 오차 및 실제 설비 적용성은 **미완료**로 남깁니다.

최신 팀원 근거 인계 변경을 포함한 전체 290 테스트와 프런트 타입·빌드 통과. Docker 빌드 설정과 CI 실제 외부 시험을 추가했으며 컨테이너/HTTPS 브라우저는 로컬 미검증입니다. 아래 기존 구현 설명은 합성 탱크의 별도 경로를 설명합니다.

## 1번

`Gateway`는 요청·검토·판단·실행을 조율합니다. 단일 프로세스 `RLock`으로 승인과 실행을 직렬화하고, report digest와 command/state/model/policy를 확인합니다. 요청별 중복 실행은 이전 결과를 반환합니다.

외부 배포용 Caddy HTTPS·공유 사이트 인증·런타임 토큰 검증·AWS 템플릿을 준비했습니다. 실제 서버 생성·공인 인증서·외부 URL은 별도 확인이 필요합니다. 다음 작업: 사용자별 인증, 실행 결과 조회·재조정. 평가 모듈은 별도 프로세스로 분리했고 접수·결과 반영만 잠금을 사용합니다. 외부 장비용 보안 경계로 사용하지 마세요.

## 2번

`simulate()`는 `cooling-demo-v3` 단일 탱크 열수지 커널입니다. 열수지와 20초 펌프 응답을 RK4로 함께 계산합니다. 동일한 초기 온도·실제 속도에서 기존 목표와 요청 목표를 비교하며 요청 구간 결과에 `cooling-assessment-v4` 장기·평형·계수 민감도를 추가합니다. 3600초 최고값·최초 초과 표본 시각·평형 온도·열 시정수와 4개 계수 ±10%의 16개 조합 결과를 반환합니다. 명목 계산이 범위를 벗어나면 전체 `out_of_domain`, 민감도 조합만 벗어나면 해당 민감도 성공 수치를 제거합니다. 실제 데이터가 없어 보정 전 상태를 명시하고 별도 학습/검증 기록으로 오프라인 보정 후보를 생성하는 도구를 제공합니다. 계수는 서버에 자동 적용하지 않습니다. [물리 평가 안내](PHYSICAL_ASSESSMENT.md)와 모델 카드를 확인하세요.

`DemoAdapter`는 SQLite에 온도·실제/목표 속도·가상 경과 시간·계산/관측 시각·지원 상태를 저장합니다. 명령 적용은 목표값만 바꾸며 실제 속도와 온도는 수동 가상 시간 진행에 따라 같은 모델로 변화합니다. 승인자용 `/demo/advance`, `/demo/sample`, `/demo/reset`으로 시간 진행·관측 갱신·초기화를 명시적으로 수행합니다. 조회나 재시작은 관측을 새로 만들거나 정지 시간을 따라잡지 않습니다. 모델 범위 이탈은 마지막 유효 상태를 보존하고 지원 불가 상태로 남기며 초기화로 복구합니다. `duration_s`는 예측 구간이며 목표값의 자동 만료·되돌림은 없습니다. 저장 스키마 v2는 기존 DB 상태를 데모 초기 온도 60°C와 가상 시간 0으로 이관하고 기록을 보존합니다. 실제 계측 연동과 물리 정확도 검증은 별도 구현 대상입니다.

가상 시간 진행·부하 변경·초기화 후에는 기존 상태 digest가 달라져 실행 단계에서 재검증을 요구합니다. 별도 프로세스의 평가 도중 이 작업을 수행하면 결과 반영 시 `hold / EVALUATION_CONTEXT_CHANGED`가 됩니다. 관측만 갱신해도 이미 접수한 평가의 이전 snapshot 유효 시간이 연장되지는 않습니다. 허용 오차나 자동 재승인 정책은 추가하지 않았으며 재검증·승인 정책은 1번 담당입니다. 가상 전용 승인 정책은 [정책 안내](VIRTUAL_POLICY.md)를 따릅니다.

## 3번

`review_evidence()`는 기본 fixture 모드에서 팀 작성 모의 카드와 degraded_cooling 시험을 반환합니다. live 모드에서는 사전 수집한 팀 작성 데모 규정을 LLM의 구조화 출력으로 검토하고 출처·원문 인용·적용 조건을 확인합니다. 실시간 문헌 검색과 실제 모델 품질 평가는 아직 수행하지 않았습니다. 실패·근거 부족은 보류하며 문서 검토자는 승인·실행 도구를 갖지 않습니다. 설정과 검증 범위는 `docs/evidence_eval.md`를 보세요.

## 4번

API 연결된 React 화면과 비교 표가 있습니다. 다음은 시계열 그래프, 근거 원문 열기, 입력 검증 UX, 오류/진행 표시 개선, 접근성, 발표 자료·영상입니다. 화면은 OpenAPI에서 자동 생성한 `api.generated.ts` 타입을 사용합니다. 계약 변경 후 `npm run generate:api`를 실행하세요.

## 이번 골격에서 제외한 것

실제 LLM 품질 평가, 진짜 논문/매뉴얼, 검증된 물리 모델, 실제 로그인, 배포 주소, PDF·영상, PLC, 자동 복구, 안전 인증. 개발 계획 문서의 P0 전체가 완료된 상태가 아닙니다.


## 1번 개발 1단계 — 공통 계약 v1.0

계산 결과·근거 카드·보고서·요청 응답을 명시적인 Pydantic 타입으로 정의했습니다. 모듈 경계에서 응답을 재검증하고, 근거 부족·범위 밖·필수 시험 누락·형식 오류는 보류합니다. 지정 v3 모델·근거·범위를 통과한 가상 요청만 담당자 승인 대기로 전환합니다. 자동 승인은 하지 않습니다.

평가 작업 상태와 revision 검사는 아래 긴 평가 작업 분리 단계에서 구현했습니다.


## 1번 개발 2단계 — SQLite 저장

`backend/gateway/storage.py`에 요청·보고서/승인 이력·가상 설비 상태·적용 영수증을 저장합니다. 기본 DB는 `data/ironman.sqlite3`, 배포 시 `IRON_MAN_DB_PATH`로 지정합니다. 데이터 파일은 Git에서 제외합니다.

API `/requests` 목록과 `/requests/{id}/history`를 추가했고 기존 API 형식은 유지했습니다. UI에서 저장된 요청을 다시 불러올 수 있습니다. 시작 시 미완료 검토는 보류, 미완료 실행은 결과 불명으로 복구합니다. 프로세스 잠금으로 동일 DB의 다중 서버를 거부합니다. 평가 작업 분리는 아래 단계에서 구현했고 외부 배포는 아직 미구현입니다.


## 1번 개발 3단계 — Docker Compose

`deploy/Dockerfile.api`, `deploy/Dockerfile.web`, `deploy/nginx.conf`, `compose.yaml`을 추가했습니다. 웹과 API를 함께 빌드·실행하고 SQLite 디렉터리를 named volume으로 유지합니다. API 컨테이너 교체 시 Nginx가 Docker DNS를 재조회합니다. API는 한 worker·비root 사용자로 실행하고 호스트에 포트를 직접 공개하지 않습니다.

기본 접속은 localhost:8080입니다. HTTPS·도메인·외부 접근 인증은 아직 배포하지 않았습니다. 긴 평가 작업은 아래 단계에서 분리했습니다. 실제 Compose 빌드·재생성 검사는 GitHub Actions의 compose job에서 확인합니다.


## 1번 개발 4단계 — 긴 평가 작업 분리

HTTP 평가 접수는 202를 반환하고 별도 spawn 프로세스에서 검토·계산합니다. 기본 동시 2개·90초 제한으로 대기열을 제한하고, 중복 평가 거절·취소·프로세스 종료·revision/작업 ID 검사·변경된 설비 상태 보류를 구현했습니다. UI는 진행 중 상태를 자동 조회합니다. [평가 작업 안내](EVALUATION.md)를 참고하세요.

다음 단계는 외부 서버의 HTTPS·데모 접근 인증·비밀키 설정입니다. 현재 가상 정책은 아래 단계와 정책 문서를 참고하세요.

## 가상 설비 전용 승인 정책

`virtual-cooling-policy-v3`는 지정 v3 커널·v4 추가 평가·DemoAdapter·합성 상태와 서버의 80°C 한계를 확인합니다. 정상·효율 저하의 요청 구간·3600초·평형·16개 민감도 조합을 검사하고 충족 시 담당자 승인 대기로 보냅니다. 승인·적용 시 같은 물리 위험과 지원 완료 여부, 상태·보고서·버전·근거를 다시 검사합니다. 실제 설비 실행 정책은 없습니다. 자세한 조건과 시연 순서는 [정책 안내](VIRTUAL_POLICY.md)를 참고하세요.
