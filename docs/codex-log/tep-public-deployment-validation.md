# 1번 관문·공개 서버 TEP 통합 검증

2026-10-09. 실행 버전 `4de39be6ad8ba6f57d75c9cd04a1c6b1a1edea51`.

2번의 `32092ca` 인계를 확인하고 이후 main의 홈·데모·근거 화면 변경까지 통합했다. TEP 초기화 프로필과 탱크 센서 snapshot의 타입을 구분하고, 냉각 전용 데모가 TEP 기록을 펌프 속도로 표시하지 않도록 제한했다. TEP 기록은 검토 콘솔에서 표시한다. 새 화면 import와 생성 예시 불일치를 수정했고 브라우저 선택자를 모델·냉각수 combobox로 특정했다.

## 관측한 검증 결과

- 실제 코어를 활성화한 로컬 전체 시험: `IRON_MAN_TEST_TEP=1 .venv/bin/pytest -q`, **290 passed**, 기존 TestClient 호환 경고 1건. TypeScript·Vite 빌드 통과.
- [GitHub CI](https://github.com/proxima1619/Iron-Man/actions/runs/37889292732): backend/frontend/compose/https 모두 성공. CI의 HTTPS는 테스트 CA를 명시적으로 신뢰하며 인증서 검증을 끄지 않는다.
- EC2의 별도 Compose에서 실제 Linux C++ 빌드, 비root 실행, GNU timeout·libstdc++ 런타임, `/data/tep-runs` 쓰기, 실제 HTTP 평가와 API·전체 스택 재생성 후 보고서 보존 확인. 이후 임시 컨테이너만 종료하고 볼륨은 보존했다.
- 공개 서버의 SQLite 온라인 백업을 서버·관리자 컴퓨터에 비공개 보관. 배포 전 6건의 기존 요청·보고서·승인·실행과 가상 상태를 원본 DB 행으로 대조하여 배포 후 동일함을 확인.
- [공개 HTTPS](https://43.201.63.65.sslip.io/#review): 공인 인증서 신뢰, 두 인증 계층, 비동기 평가 202, 실제 TEP XMV10=42·XMV11=19의 600초 결과, XMV10=0 코어 정지·101 지원 범위 밖의 보류, 승인·실행 409 확인.
- 실제 Chrome: 홈페이지, 탱크 차단·담당자 승인·가상 적용·상태 변경 후 재검증, TEP 두 입력의 기준/변경 그래프·completed 표시·승인/실행 비활성, 냉각 전용 저장 기록 조회 확인. 브라우저 런타임 오류 없음.
- 공개 시험 뒤 API 컨테이너를 다시 생성하여 **18건**의 요청·보고서·판단·실행 영수증·감사 이력이 재시작 전 API 응답과 완전히 동일함을 확인. 가상 탱크는 60°C·부하 1·속도 100%로 초기화하고 기록은 유지.

## 유지한 정책과 한계

- `tep-sim-01 / set_tep_cooling_water`, XMV10/XMV11의 단위는 `percent_full_scale`. 펌프 속도와 구분한다.
- `report.tep_simulation`과 출처·빌드 해시·시드·초기 상태·단위·시계열을 보존한다. `report.snapshot`은 초기화 프로필이며 현장 계측값이 아니다.
- 성공 계산도 `hold / TEP_POLICY_NOT_CONFIGURED / can_approve=false`. 실패나 범위 밖도 보류하며 승인·실행 권한으로 이를 우회할 수 없다.
- 탱크의 80°C·최소 펌프 속도·효율 0.65와 근거 fixture를 TEP 판정에 재사용하지 않는다.
- TEP 전용 위험·근거·재검증 정책, 외란·고장 시험 확장, 실측 오차 및 실제 설비 적용성은 미완료다. 코어 실행 성공을 안전성·현장 재현도 검증으로 표현하지 않는다.
- 공개 서버에 실제 LLM API 키는 연결하지 않았다. 외부 논문 검토·LLM 피드백의 실제 호출 검증은 이 배포 결과에 포함하지 않는다.
