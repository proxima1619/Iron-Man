# 저장 기록의 실시간 AI 설명

## 흐름

DB 기록 선택 → 저장된 명령·시나리오 결과·가상 적용 기록 확인 → AI 피드백 받기.
`POST /requests/{request_id}/feedback`는 기존 역할 토큰으로 인증한다.
명시적인 요청마다 API를 호출하며, 실제 API 키와 모델이 필요하다.
로컬 논문 또는 Europe PMC 검색 문헌을 기존 수집 모듈로 가져온다.

게이트웨이 잠금 안에서 기록을 복사한 후 잠금을 해제하고 LLM을 호출한다.
현재 설비의 관측 시각·안전 정책으로 과거 설명을 차단하지 않는다.
기록의 revision·report digest·분석 입력 SHA256과 생성 시각을 응답에 포함한다.
원래 요청·보고서·승인·상태·실행 기록은 수정하지 않는다.
피드백은 응답으로만 제공하며 새로고침 후 다시 요청할 수 있다.

## 경계

- 승인자 신원, 감사 기록, 요청자 연락처를 모델 입력에서 제외했다.
- 실측 반응, 합성 예측, 가상 목표 적용을 구분하도록 명시했다.
- 원문 인용 및 적용 조건은 기존 검증 모듈을 거친다. 실행 시험 제안은 금지한다.
- 지지·반례 부재는 부족 조건으로 표시한다. LLM 설명 자체가 현실 안전 증거는 아니다.
- API 인증·권한·한도·연결·출처·인용 검증 오류를 민감 값 없는 메시지로 표시한다.
- 동시 피드백은 최대 2개다. 서버의 API 응답 대기는 기존 20초(설정 최대 60초)다.
- UI는 120초까지 기다리며, 선택 기록이나 토큰 변경 시 이전 응답을 버린다.

## INVALID_STATE 확인

실행 중인 로컬 서버에서 센서 valid, 모델 범위 ready, 관측 후 약 2493초를 확인했다.
상태 유효 시간은 60초이므로 검토 시작 전에 보류된 것이 원인이다.
서버 사유에 센서 불량·모델 범위·미래 시각·관측 경과 초를 구분해 표시한다.
가상 상태 다시 읽기는 기존 `/demo/sample`을 명시적으로 호출하며 과거 기록을 바꾸지 않는다.
실제 운영의 시간 검사와 승인 유효성 검사는 유지한다.

## 확인 범위

Python 문법 컴파일·프런트 타입 검사를 수행했다. 실제 API 피드백은 서버 재시작 후
사용자의 키로 실행해야 한다. 키를 읽거나 유료 API 호출을 수행하지 않았다.
