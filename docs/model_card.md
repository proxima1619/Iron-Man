# 냉각 탱크 데모 모델 카드

버전: `cooling-demo-v2`. 대상은 합성 초기 상태를 가진 단일 냉각 탱크와 펌프다. 실제 PLC나 설비와 연결되지 않는다. 모델 파라미터는 `backend/simulator/model.py`의 변경 불가 설정으로 관리한다.

## 계산

탱크 전체가 하나의 온도를 갖는다고 가정하고 다음 열수지와 펌프 응답을 함께 계산한다.

```text
C × dT/dt = Q_nominal × load_ratio − UA_nominal × (s / 100) × efficiency × (T − T_coolant)
ds/dt = (target_pct − s) / tau
```

`T`는 탱크 온도(°C), `s`는 실제 응답을 나타내는 유효 펌프 속도(%)다. `UA_nominal`은 열교환계수와 면적을 합친 유효 열전달 계수다. 온도 차이 1°C는 1K와 같으므로 열전달량은 W로 계산한다.

| 파라미터 | 데모 값 | 단위 |
|---|---:|---|
| 유효 열용량 `C` | 200,000 | J/K |
| 정격 발생 열량 `Q_nominal` | 35,000 | W |
| 최대 속도 유효 열전달 계수 `UA_nominal` | 1,000 | W/K |
| 고정 냉각수 온도 `T_coolant` | 25 | °C |
| 펌프 응답 시정수 `tau` | 20 | s |
| 정상 / 효율 저하 조건의 `efficiency` | 1.0 / 0.65 | 무차원 |
| 온도 제한 | 80 | °C |

열전달량을 온도 차이에 비례시키는 식의 근거는 [MathWorks의 대류 열전달 설명](https://www.mathworks.com/help/simscape/ref/convectiveheattransfer.html)이다. 위 수치와 펌프 속도에 대한 선형 비례는 이 프로젝트가 정한 데모 가정이며 해당 자료에서 가져온 파라미터가 아니다. 실측 보정값이나 산업 안전 기준이 아니다.

기본 1초 간격의 4차 Runge–Kutta(RK4)로 온도와 펌프 속도를 함께 적분한다. `duration_s`는 API가 허용하는 1~3,600초이고 기본값은 300초다. 내부 `_run()`은 수렴 검증을 위해 1초 이하 간격도 지원한다. 냉각수 온도에 가까워지면 냉각량이 줄어들고, 탱크가 냉각수보다 차가우면 열전달 방향이 반대로 바뀐다. 출력 온도를 임의로 잘라 범위에 맞추지 않는다.

정상 조건에서 온도 60°C, 부하 비율 1.0, 펌프 속도 100%는 발생 열량과 방출 열량이 같은 평형 상태다. 일정한 양의 펌프 속도에서 평형 온도는 `25 + 35000 × load_ratio / (1000 × (s / 100) × efficiency)`다. 무부하에서 펌프가 작동하면 냉각수 온도에 접근하며, 펌프가 멈추면 이 모델의 열교환 항은 0이 된다.

기존 속도 유지와 요청 속도 적용은 동일한 온도·부하·펌프 속도·효율에서 시작한다. 내부 계산은 초기 상태와 각 적분 단계의 온도, 최고 온도, 최초 한계 초과 시각을 추적한다. 현재 팀 공통 API v1.0에는 시나리오별 최고 온도와 한계 초과 여부만 반환한다. 반올림 전 최고 온도의 80°C **초과**만 위반으로 처리한다. 최고 온도는 초기 상태도 포함하는 계산 단계의 표본값이며 연속 시간의 정확한 극값이나 초과 시각을 보장하지 않는다.

## 입력 범위와 한계

온도 0~120°C, 부하 비율 0~1.5, 펌프 속도 0~100%, 유효한 센서 품질, 양의 유한 관측 시각만 지원한다. 초기 입력뿐 아니라 각 적분 단계가 끝날 때 반올림 전 온도와 유효 펌프 속도가 유한한 값이며 지원 범위 안에 있는지 검사한다. 기존 속도 유지 또는 요청 속도 적용 중 하나라도 범위를 벗어나면 이전에 완료한 시나리오의 수치도 내보내지 않고 전체 결과를 `out_of_domain`, 빈 `scenarios`로 반환한다. `limitation`에 해당 시나리오, 계산 분기, 시각과 사유를 기록한다. 관측 시각의 노후 여부는 호출 시각이 필요한 1번 관문 서버에서 검사한다.

80°C 안전 한계와 120°C 모델 상한은 서로 다른 기준이다. 계산이 지원 범위 안에서 80°C를 넘으면 `completed`와 `exceeded=true`이고 관문이 차단한다. 계산이 지원 범위를 벗어나면 안전 판정에 쓸 수 없으므로 `out_of_domain`이고 관문이 보류한다.

모델은 탱크 내부의 온도 분포, 외기와의 열교환, 냉각수 온도의 시간 변화, 열용량 변화, 유량 곡선, 열교환기의 비선형성, 센서 오차, 통신 지연, 전력 소비를 재현하지 않는다. 합성 데이터로 흐름과 물리적 성질을 검증할 뿐 실제 설비의 정확도나 안전성을 입증하지 않는다. `mock=false`는 고정 응답 대신 계산을 수행한다는 뜻이며 실측 검증을 의미하지 않는다. 팀의 v1.0 관문 정책은 이 결과가 한계를 넘으면 차단하고, 넘지 않아도 승인 정책 미설정으로 보류한다.

시뮬레이션은 상태를 읽기만 한다. 가상 설비의 명령값 변경은 승인 후 관문 서버가 별도 `DemoAdapter`를 호출할 때만 일어난다. 현재 어댑터는 온도 60°C를 반환하고 펌프 속도를 즉시 목표값으로 저장한다. v2 계산의 시간 경과와 응답 지연을 어댑터 상태에 반영하는 기능은 아직 없다.
