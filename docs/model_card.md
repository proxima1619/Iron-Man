# 냉각 탱크 데모 모델 카드

버전: `cooling-demo-v3`. 대상은 합성 초기 상태를 가진 단일 냉각 탱크와 펌프다. 실제 PLC나 설비와 연결되지 않는다. 모델 파라미터는 `backend/simulator/model.py`의 변경 불가 설정으로 관리한다. v3는 v2의 열수지·펌프 응답식과 계수를 유지하면서 같은 계산 커널을 지속되는 가상 설비 상태에도 적용한다.

추가 평가는 `cooling-assessment-v4`로 구분한다. 요청 구간과 별도로 3600초·평형 온도·열 시정수 및 계수 민감도를 반환한다. 계수와 상태의 물리 커널이 같아 저장된 v3 상태는 유지하지만 관문 정책은 v3로 올라가 이전 승인을 재검증한다. 세부 방법과 보정 입력 형식은 [물리 평가 안내](PHYSICAL_ASSESSMENT.md)를 참고한다. 실제 계측 기록이 없어 기본 계수는 여전히 보정 전이다.

## 계산

탱크 전체가 하나의 온도를 갖는다고 가정하고 다음 열수지와 펌프 응답을 함께 계산한다.

```text
C × dT/dt = Q_nominal × load_ratio − UA_nominal × (s / 100) × efficiency × (T − T_coolant)
ds/dt = (target_pct − s) / tau
```

`T`는 탱크 온도(°C), `s`는 실제 응답을 나타내는 유효 펌프 속도(%)다. `UA_nominal`은 열교환계수와 면적을 합친 유효 열전달 계수다. 온도 차이 1°C는 1K와 같으므로 열전달량은 W로 계산한다.

| 파라미터 | 데모 값 | 단위 |
|---|---:|---|
| 유효 열용량 `C` | 200,000 | J/K |
| 정격 발생 열량 `Q_nominal` | 35,000 | W |
| 최대 속도 유효 열전달 계수 `UA_nominal` | 1,000 | W/K |
| 고정 냉각수 온도 `T_coolant` | 25 | °C |
| 펌프 응답 시정수 `tau` | 20 | s |
| 정상 / 효율 저하 조건의 `efficiency` | 1.0 / 0.65 | 무차원 |
| 온도 제한 | 80 | °C |

열전달량을 온도 차이에 비례시키는 식의 근거는 [MathWorks의 대류 열전달 설명](https://www.mathworks.com/help/simscape/ref/convectiveheattransfer.html)이다. 위 수치와 펌프 속도에 대한 선형 비례는 이 프로젝트가 정한 데모 가정이며 해당 자료에서 가져온 파라미터가 아니다. 실측 보정값이나 산업 안전 기준이 아니다.

기본 1초 간격의 4차 Runge–Kutta(RK4)로 온도와 펌프 속도를 함께 적분한다. `duration_s`는 요청의 예측 구간으로 API가 허용하는 1~3,600초이고 기본값은 300초다. 적용 목표값의 자동 만료나 되돌림 시간은 아니다. 내부 `_run()`은 수렴 검증을 위해 1초 이하 간격도 지원한다. 냉각수 온도에 가까워지면 냉각량이 줄어들고, 탱크가 냉각수보다 차가우면 열전달 방향이 반대로 바뀐다. 출력 온도를 임의로 잘라 범위에 맞추지 않는다.

정상 조건에서 온도 60°C, 부하 비율 1.0, 펌프 속도 100%는 발생 열량과 방출 열량이 같은 평형 상태다. 일정한 양의 펌프 속도에서 평형 온도는 `25 + 35000 × load_ratio / (1000 × (s / 100) × efficiency)`다. 무부하에서 펌프가 작동하면 냉각수 온도에 접근하며, 펌프가 멈추면 이 모델의 열교환 항은 0이 된다.

기존 목표 속도 유지와 요청 목표 속도 적용은 동일한 온도·부하·실제 펌프 속도·효율에서 시작한다. 실제 속도가 목표에 도달하지 않았다면 기존 설정 분기도 기존 목표를 향해 계속 응답한다. 과거 스냅샷에 목표값이 없으면 실제 속도를 기존 목표로 사용한다. 기본 최고값과 `exceeded`는 요청 구간을 뜻하며, 추가 `physical_assessment`에 장기 최고값·최초 초과 표본 시각·평형·민감도를 반환한다. 반올림 전 최고 온도의 80°C **초과**만 위반으로 처리한다. 최고 온도는 초기 상태도 포함하는 계산 단계의 표본값이며 연속 시간의 정확한 극값이나 초과 시각을 보장하지 않는다.

## 입력 범위와 한계

온도 0~120°C, 부하 비율 0~1.5, 실제/목표 펌프 속도 0~100%, 유효한 센서 품질, 양의 유한 관측 시각과 지원 가능한 모델 상태만 지원한다. 초기 입력뿐 아니라 각 적분 단계가 끝날 때 반올림 전 온도와 유효 펌프 속도가 유한한 값이며 지원 범위 안에 있는지 검사한다. 기존 목표 속도 유지 또는 요청 목표 속도 적용 중 하나라도 범위를 벗어나면 이전에 완료한 시나리오의 수치도 내보내지 않고 전체 결과를 `out_of_domain`, 빈 `scenarios`로 반환한다. `limitation`에 해당 시나리오, 계산 분기, 시각과 사유를 기록한다. 관측 시각의 노후 여부는 호출 시각이 필요한 1번 관문 서버에서 검사한다.

80°C 안전 한계와 120°C 모델 상한은 서로 다른 기준이다. 계산이 지원 범위 안에서 80°C를 넘으면 `completed`와 `exceeded=true`이고 관문이 차단한다. 계산이 지원 범위를 벗어나면 안전 판정에 쓸 수 없으므로 `out_of_domain`이고 관문이 보류한다.

모델은 탱크 내부의 온도 분포, 외기와의 열교환, 냉각수 온도의 시간 변화, 시간에 따른 열용량 변화, 유량 곡선, 열교환기의 비선형성, 센서 오차, 통신 지연, 전력 소비를 재현하지 않는다. 합성 데이터로 흐름과 물리적 성질을 검증할 뿐 실제 설비의 정확도나 안전성을 입증하지 않는다. `mock=false`는 고정 응답 대신 계산을 수행한다는 뜻이며 실측 검증을 의미하지 않는다. 관문은 지정된 가상 모델·시험·근거 정책을 통과한 요청만 담당자 승인 대기로 보낸다. 실제 설비 실행 정책은 없다.

## 지속되는 가상 설비 상태

예측 시뮬레이션은 상태를 읽기만 한다. 승인 후 관문 서버가 `DemoAdapter`를 호출하면 목표 속도만 저장하며 온도와 실제 속도는 그대로 유지한다. 승인자용 `POST /demo/advance`의 `seconds_s`만큼 수동으로 가상 시간을 진행할 때 위 계산 커널로 실제 속도와 온도를 변화시키고 SQLite에 저장한다. 실제 가상 설비는 정상 효율 1.0을 사용하며, 효율 저하는 예측 시험 조건이다. 목표값은 다음 명령이나 명시적인 초기화까지 유지한다.

저장 상태에는 온도, 실제/목표 속도, 부하, 가상 경과 시간 `simulation_time_s`, 모델 버전, 계산 시각 `calculated_at`, 관측 시각 `observed_at`, revision과 지원 상태가 포함된다. `GET /state`는 상태와 시각을 바꾸지 않는다. `POST /demo/sample`은 물리 상태를 움직이지 않고 현재 합성 상태의 관측 시각을 갱신한다. 서버를 재시작해도 저장 상태부터 이어가며 정지한 벽시계 시간을 자동 적분하지 않는다.

가상 시간 진행 중 모델 범위에서 벗어나면 마지막 유효 온도·속도를 저장하고 `domain_status=out_of_domain`·센서 불량·사유를 남긴다. 관측 갱신으로 지원 불가를 지우지 않는다. `POST /demo/reset`은 60°C·부하 1.0·실제/목표 100%·가상 시간 0의 데모 초기 상태로 되돌리고 revision을 증가시킨다. 요청·보고서·승인·적용 영수증 이력은 보존한다.

가상 시간 진행·부하 변경·초기화로 승인 당시 상태와 달라지면 실행 단계의 기존 정확 일치 검사에서 재검증을 요구한다. 관측 시각은 상태 digest에 포함되지 않지만 관측 노후와 승인 만료 검사에는 사용한다. 허용 오차나 자동 재승인 정책은 추가하지 않았다. 재검증 정책은 1번 담당의 범위다.
