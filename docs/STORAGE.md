# SQLite 저장과 재시작

## 실행·경로

기존 실행 명령을 그대로 사용합니다. FastAPI 시작 시 저장소를 열고, 종료 시 닫습니다. 모듈 import나 OpenAPI 내보내기는 운영 DB를 열지 않습니다.

이전 버전 프로세스에만 남아 있던 메모리 기록의 자동 이관은 포함하지 않습니다. 새 버전에서 생성한 기록부터 저장합니다.

기본 파일은 저장소 루트의 `data/ironman.sqlite3`입니다. 원하는 경로는 환경변수로 지정합니다.

```bash
export IRON_MAN_DB_PATH=/absolute/path/ironman.sqlite3
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

`/absolute/path/ironman.sqlite3`는 자신의 경로로 바꾸는 예시입니다. `.env` 자동 로딩은 없습니다. 부모 디렉터리는 자동 생성하고 파일을 읽거나 쓸 수 없으면 시작에 실패합니다. 잘못된 DB를 빈 DB로 덮어쓰지 않습니다.

Linux/macOS는 파일 잠금, Windows는 바이트 잠금으로 같은 DB의 서버 중복 실행을 막습니다. 이번 실행 검증은 macOS에서 했으며 Windows 실행은 미검증입니다. 프로세스가 종료되면 OS 잠금이 해제됩니다. `.lock` 파일이 남아 있어도 사용 중이라는 뜻은 아닙니다. 사용 중인 DB나 잠금 파일을 삭제하지 마세요. `--workers 1`로 실행합니다.

## 저장하는 정보

| 테이블 | 내용 |
|---|---|
| requests | 입력, 현재 상태, 최신 보고서·승인·실행, 누적 이벤트 |
| reports | request ID + 보고서 digest별 이전 보고서와 당시 snapshot |
| approvals | request ID + report digest별 승인자·사유·만료 |
| demo_state | 가상 펌프 설정, 부하, 센서 품질, 상태 revision |
| adapter_executions | execution ID별 적용 결과와 명령·상태 |

재검증으로 현재 승인이 무효화되어도 이전 보고서와 승인 이력은 남습니다. 거절 사유는 요청의 이벤트 기록에 남습니다. 스키마 버전은 `PRAGMA user_version=1`이며, 더 새로운 버전의 DB는 열지 않습니다.

## 재시작 동작

| 종료 당시 상태 | 재시작 후 |
|---|---|
| 접수·차단·보류·승인 대기·거절 | 그대로 조회 가능 |
| 승인 완료 | 승인 유지. 실행 시 만료·상태·명령·버전을 다시 검사 |
| 검토 중 | 비정상 종료 후 hold, 현재 report/approval 제거, evaluation은 interrupted. 정상 종료 시 cancelled 보류 보고서 저장. 사용자가 재검증 |
| 실행 중 | execution_unknown; execution ID 유지, 자동 재전송 금지 |
| 실행 완료 | 완료 기록·가상 상태 유지. 같은 요청의 재실행 호출은 기존 결과 반환 |

실행 예약을 먼저 commit하고 어댑터를 호출합니다. 가상 어댑터는 상태 변경과 적용 영수증을 한 트랜잭션으로 저장합니다. 적용 직후 서버가 꺼져 응답을 저장하지 못한 경우에도 실행 결과를 보수적으로 불명으로 표시합니다. 운영자용 확인·조정 API는 다음 과제이며, 불명 요청을 완료로 임의 수정하지 않습니다.

이 원자성은 **같은 DB에 있는 가상 설비에만 해당**합니다. 실제 PLC·외부 시스템 적용까지 SQLite 트랜잭션으로 보장하는 것은 아닙니다.

## 확인 방법

1. 요청을 생성하고 검토합니다. 현재 합성 모델 60% 요청은 차단, 80%는 승인 정책 미설정 보류가 예상됩니다.
2. 백엔드 프로세스를 정상 종료하고 같은 DB 경로로 다시 시작합니다.
3. 화면의 `저장된 요청 불러오기`에서 요청을 선택합니다.
4. 같은 보고서·이벤트가 표시되는지 확인합니다.

승인·실행의 재시작 시험은 테스트 전용 모의 정책에서 수행합니다. 실제 계산 결과 승인 정책을 변경한 것은 아닙니다.

```bash
.venv/bin/pytest -q tests/test_persistence.py
```

테스트는 임시 디렉터리의 DB를 사용합니다. 실제 자식 프로세스를 종료하여 실행 전·적용 직후·검토 중 중단을 재현합니다.

## 배포·보관

- Docker Compose는 DB의 **부모 디렉터리 전체** `/data`를 `gateway-data` 영구 볼륨에 연결합니다. [Docker 안내](DOCKER.md)를 참고하세요. 컨테이너 내부 임시 파일만 사용하면 교체 시 사라집니다.
- SQLite는 WAL 모드·synchronous FULL로 사용합니다. 운영 중 `.sqlite3` 파일 하나만 복사하면 WAL의 최신 데이터를 놓칠 수 있습니다. SQLite backup API를 쓰거나 서버를 정상 종료한 뒤 백업하세요.
- 데이터는 Git에 올리지 않습니다. DB·WAL·공유 메모리·잠금 파일을 `.gitignore`에 추가했습니다.
- DB 잠금·저장 실패는 API 503으로 반환하고 성공으로 표시하지 않습니다. 실행 결과 불명 상태는 재실행으로 해결하지 않습니다.
- 현재 조회 목록은 소규모 데모용이며 전체 기록을 반환합니다. 데이터 보존·삭제 정책과 페이지네이션은 후속입니다.
