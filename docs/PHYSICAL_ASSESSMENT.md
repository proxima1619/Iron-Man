# 물리 환경 보완: 장기 위험과 계수 보정

현재 물리 커널은 `cooling-demo-v3`, 추가 평가 버전은 `cooling-assessment-v4`, 관문 정책은 `virtual-cooling-policy-v3`입니다. 열수지식과 기본 계수를 유지했으므로 기존 SQLite 물리 상태의 모델 버전이나 DB 구조를 바꾸지 않습니다. 평가 기준은 달라졌으므로 이전 정책으로 받은 승인은 다시 평가해야 합니다.

## 1. 요청 구간 이후의 위험

명령의 `duration_s`는 예측 구간이며 적용 목표값의 만료 시간이 아닙니다. 각 시나리오와 기존/요청 분기에 다음 검사를 추가했습니다.

- 요청 구간의 최고 온도: 기존 `baseline_peak_c`, `candidate_peak_c`, `exceeded` 의미를 유지합니다.
- 3,600초 계산: 최고 온도와 최초 80°C 초과 표본 시각을 반환합니다. 기본 적분 간격은 1초이며 연속 시간의 정확한 초과 시각은 아닙니다.
- 일정 조건의 평형 온도와 열 시정수: `T_eq = T_coolant + Q × load / (UA × target/100 × efficiency)`, `tau_thermal = C / (UA × target/100 × efficiency)`입니다. 펌프가 목표에 도달하고 부하·효율·냉각수 온도가 계속 일정하다는 가정입니다.
- 냉각량이 0이면 유한 평형을 지어내지 않습니다. 발열이 있으면 `unbounded_heating`, 발열도 없으면 `no_unique_equilibrium`입니다. 3,600초 적분 자체가 범위를 벗어나면 전체 결과가 `out_of_domain`이며 성공 수치는 없습니다.

### 위험이 달라지는 예

초기 온도 60°C, 부하 1.0, 실제/기존 목표 100%, 요청 80%, 냉각 효율 0.65에서:

| 검사 | 결과 |
|---|---:|
| 요청 300초 최고 온도 | 약 77.268°C |
| 최초 한계 초과 표본 | 378초 |
| 3,600초 최고 온도 | 약 92.305°C |
| 일정 조건의 평형 온도 | 약 92.308°C |

이 요청은 이제 `blocked / LIMIT_EXCEEDED`입니다. 3,600초 안에 한계를 넘지 않아도 평형 온도가 한계를 넘으면 차단합니다. 평형 온도는 모델 식의 해석값이며 지원 범위를 벗어난 실제 온도의 정확한 예측을 뜻하지 않습니다. 시간이 변하는 부하·고장·냉각수 조건과 무기한 안전을 보장하지 않습니다.

## 2. 계수 민감도

열용량·발열·열전달·펌프 응답의 각 기본값에 **±10%를 가정**하고 16개 끝점 조합을 동시에 시험합니다. 기존/요청 분기마다 3,600초 최고 온도와 평형 온도의 가장 큰 값을 반환합니다. 내부 계산은 각 조합의 동일 초기 온도·실제 속도에서 다시 시작합니다.

| 계수 | 최소 | 최대 | 단위 |
|---|---:|---:|---|
| 열용량 | 180,000 | 220,000 | J/K |
| 발열 | 31,500 | 38,500 | W |
| 열전달 | 900 | 1,100 | W/K |
| 펌프 응답 시정수 | 18 | 22 | s |

이 범위는 실측값·표준편차·95% 신뢰구간이 아닙니다. 끝점 시험은 범위 내부 모든 조합의 수학적 최대를 증명하지 않습니다. 냉각수 온도, 부하 및 각 시나리오의 효율은 변동 대상에서 제외한 고정 가정입니다. 별도의 민감도 프로파일은 아직 지원하지 않습니다.

어느 조합이든 적분 도중 모델 범위를 벗어나면 민감도 결과는 `out_of_domain`이고 모든 민감도 최고값은 null입니다. 명목 계산은 완료된 경우 유지합니다. 명목 시험에서 확인된 위반은 차단하고, 확인된 위반 없이 민감도 지원을 완료하지 못하면 보류합니다. 정상·효율 저하, 기존/요청, 장기·평형·민감도 모든 검사에서 한계를 넘지 않아야 가상 승인 대기로 갈 수 있습니다.

따라서 초기 부하 1.0의 100% 요청도 민감도 시험에서는 차단됩니다. 가상 승인 흐름은 부하를 **0.6**으로 명시적으로 바꾼 뒤 80% 요청으로 확인합니다. 같은 효율 저하 조건에서 요청의 최악 평형값은 약 **74.359°C**입니다. 실제 설비 승인으로 해석하지 않습니다.

## 실측 보정 도구

저장소에서 실제 계측 시계열을 확보하지 못했습니다. 런타임 결과에는 `calibration_status=not_calibrated`, `parameter_origin=demo_assumption`을 표시합니다. 새 도구는 데이터가 도착했을 때 보정 후보를 생성하기 위한 **오프라인 도구**입니다.

```powershell
.\.venv\Scripts\python.exe -m scripts.calibrate_model --input examples/simulator/calibration-synthetic.json --output examples/simulator/calibration-synthetic-result.json
```

예제와 결과는 모두 `data_origin=synthetic`이며 물리 정확도 입증 자료가 아닙니다. 예제 생성식의 계수는 발열 38,000 W, 열전달 1,100 W/K, 펌프 응답 28초이고 런타임 기본 계수와 다릅니다. `scripts/generate_calibration_example.py`로 재생성할 수 있습니다.

입력 형식은 `examples/simulator/CalibrationDataset.schema.json`을 참고하세요. 실제 기록에는 다음 자료가 필요합니다.

- 출처 ID, `data_origin=measured`, 별도의 후보 모델 버전.
- 독립적으로 확보한 학습/검증 기록 각각 최소 1개. 같은 ID·같은 기록 재사용은 거절합니다. 내용 중복 검사는 실제 수집 독립성을 인증하지 않으므로 수집자가 확인해야 합니다.
- 열용량 **J/K** 기준값과 근거. 온도 데이터만으로는 Q/C와 UA/C만 식별할 수 있어 C·Q·UA를 동시에 임의 보정하지 않습니다.
- 일정 냉각수 온도 **°C**와 근거, 기록별 일정 효율, 측정 시각 **초**, 온도 **°C**, 실제 속도·목표 속도 **%**, 부하 비율.
- 목표 속도/부하는 각 샘플 시각부터 다음 샘플 직전까지 일정한 값입니다. 중간 명령 변경을 누락하면 안 됩니다. 각 기록은 0초부터 시작하며 간격은 0.1초 이상입니다.
- 펌프 속도 변화 및 발열·열전달을 구분할 수 있는 부하/속도 변화. 변화가 부족하거나 회귀식의 정보가 부족하면 보정을 거절합니다.
- 사용자가 정한 검증 허용 오차: 온도 RMSE, 온도 최대 절대 오차, 속도 RMSE.

펌프 응답은 지수 응답으로, 발열·열전달은 열수지 회귀 초기값과 동일 RK4 커널의 궤적 오차 최소화로 보정합니다. 다음 측정값으로 상태를 매번 되돌리지 않고 기록 전체를 초기 상태부터 예측합니다. 검증 기록은 계수 추정에 사용하지 않습니다. 수치 최적화가 전역 유일해를 보장하지 않으며 측정 노이즈에 대한 확률적 불확실성도 추정하지 않습니다.

탐색 범위는 발열 1,000~150,000 W, 열전달 100~5,000 W/K, 펌프 응답 2~120초입니다. 범위 경계 근처의 추정은 검증 통과로 처리하지 않습니다. 한 기록 최대 3,600초·1,000샘플, 학습/검증 합계 최대 7,200초·4,000샘플로 작업량을 제한합니다. 긴 기록은 의미 있는 독립 실험으로 구성하고 최초 상태/명령 시각을 보존하세요.

출력에는 검증 후 정규화한 입력 내용의 해시, 출처 선언, 기준값 근거, 학습/검증 ID, 추정 계수, 두 기록 집합의 오차, 허용 오차, 경계 여부를 남깁니다. 파일 바이트의 진위 인증은 아닙니다. `validation_passed`는 지정 기록/허용 오차의 통과 여부이며 현실 안전 인증이 아닙니다. `activated=false`, `usage=offline_candidate_only`로 반환하고 서버 설정·DB·기존 모델을 자동 변경하지 않습니다. 채택하려면 1·2번이 실측 근거, 입력 범위, 독립 검증, 별도 모델 버전과 승인 정책을 검토해야 합니다.

## API와 인계

`ScenarioResult.physical_assessment`에 위 결과를 추가했습니다. 과거 보고서에는 null이 허용되지만 새 승인 정책은 평가 누락을 보류합니다. 타입 원본은 `backend/contracts.py`; 생성된 JSON 스키마·OpenAPI·TypeScript도 함께 갱신합니다.

이번에는 시간에 따라 발생하는 고장과 센서 관측/실제 상태 분리 기능을 추가하지 않았습니다. 다음 물리 보완 전에 실제 계측 기록, C의 근거, 냉각수 온도 및 부하의 측정 방법을 확보하는 것이 필요합니다.
