# 4번 홈페이지·근거 화면 인계

## 진입

- `/`: 프로젝트 소개, 냉각 펌프 검토 흐름, API 상태 확인.
- `/#demo`: 별도 데모 체험 화면. 홈페이지 아래에 삽입하지 않는다.
- `/#review`: 기존 담당자 검토 콘솔. 입력·계산 비교·근거·승인·가상 실행.
- 근거 링크의 `#evidence-<id>`는 콘솔을 유지하며 해당 카드로 이동한다.
- 토큰은 콘솔에 직접 입력하고 브라우저 저장소에 보관하지 않는다.

## 홈페이지 체험·밝은 테마 후속 변경

### DB 기록 선택과 설명

홈페이지 체험의 `데이터베이스 기록 불러오기`는 인증된 `GET /requests`를,
드롭다운 선택은 `GET /requests/{id}`를 호출한다. 현재 SQLite의 실제 저장 기록을
읽으며 프런트 예시 배열이나 가짜 결과를 사용하지 않는다. 속도·상태·요청 ID와
근거 카드 개수로 기록을 구분한다. 조회 시점에 5개 기록이 있었고 60% 차단 및
80% 적용 완료 기록에는 계산 결과와 모의 근거 카드가 각각 저장되어 있었다.

선택한 기록의 스냅샷·모델·정책·예측 구간, 시나리오별 최고 온도 차이와 제한
초과 폭을 숫자 그대로 설명한다. 적용 접수 기록은 예측과 실측이 일치했다는 검증과
구분한다. 근거 카드는 접힌 영역에 숨기지 않고 결과 아래 바로 표시한다.

근거 없는 보류 기록도 서버 사유·계산 및 문헌의 누락 상태를 보여준다. 존재하지
않는 논문·인용·적용 조건을 생성하지 않는다. 보고서가 전혀 없는 요청은 사용자가
`현재 설비 상태로 이 요청 검토`를 선택할 수 있고 이는 과거 스냅샷 재연이 아니다.
합성 저장 기록을 실측 운전 이력으로 표시하지 않는다.

- 홈페이지와 검토 콘솔을 흰색 표면·연보라색 배경·보라색 강조로 통일했다.
  위험/보류 상태는 읽을 수 있도록 빨강/황토색 의미 색상을 유지했다.
- 홈페이지 설명 목록은 `display:block`으로 전용 배치를 설정했다. 전역 `dl`
  그리드가 목록의 중첩 div를 좁게 만들어 글자가 한 글자씩 줄바꿈되던 문제를 수정했다.
- `/#demo`에 실제 API를 사용하는 `DemoExperience`를 추가했다. 60%/80% 요청,
  비동기 결과 조회, 근거 확인, 이유·체크박스 입력, 승인, 별도 가상 적용을 제공한다.
- `초기 상태로 준비`는 사용자가 누를 때만 기존 `/demo/reset`을 호출한다.
  요청 이력을 지우지 않으며 공유 가상 상태 변경으로 이전 승인은 재검증이 필요할 수 있다.
- 기본 로컬 역할 토큰은 공개 데모 값이며 개인 신원 인증이 아니다. 토큰을
  브라우저 저장소에 보관하지 않으며 수정된 서버 토큰은 체험 연결 설정에서 입력한다.
- 실제 설비가 연결되지 않은 demo_only 서버인지 체험 시작·승인·적용 전에 확인한다.
  최종 권한·차단·보고서·상태·만료 검사는 기존 서버에서 수행한다.
- SMTP 알림 발송, 실제 설비 실행, 사전 가짜 성공 결과는 추가하지 않았다.
- 타입 검사 통과, 실행 중인 Vite의 신규 TSX·CSS 변환 응답과 `/api/health` 200 확인.
  이번 후속 변경에서 브라우저 클릭 검증이나 추가 테스트는 실행하지 않았다.

## 근거 화면

`EvidencePanel.tsx`는 3번의 응답과 1번의 최종 판단을 표시한다.

| 표시 | 응답의 확인 근거 |
|---|---|
| 모의 응답 | `evidence.mock=true` |
| 사전 수집 논문 | `limitation`이 `사전 수집 문서 검토`로 시작하고 paper 카드 존재 |
| 사전 수집 문서 | 같은 수집 경로, paper 카드 없음 |
| 실시간 검색 | `limitation`이 `실시간 Europe PMC 논문 검색·원문 수집`으로 시작 |
| 수집 방식 확인 불가 | 실패·이전 응답 등 수집 경로를 확인할 정보가 없음 |

URL에 논문 도메인이 있다는 이유로 실시간 검색이라고 추정하지 않는다. 현재
공통 계약에는 수집 방식의 구조화 필드가 없어 3번의 명시적 설명 접두사를 사용한다.
3번이 이 표현을 변경하거나 실패 응답까지 구분하려면 acquisition/source mode
필드 추가를 1·3·4번과 합의해야 한다. 이번 변경에서 3번과 승인 정책을 바꾸지 않았다.

각 카드에는 출처 링크, 원문 인용, 주장, 적용 조건, 일치 조건, 부족·미확인 조건,
원문 위치, 저자/발행 정보, 버전, 이용 조건, 추가 시험의 계수 출처가 있다.
인용문·조건·링크가 없으면 누락 상태를 표시한다. 링크는 HTTP(S)만 허용하고
새 창에서 원문을 연다. React의 기본 텍스트 이스케이프를 사용한다.

최종 서버 판단이 `hold / EVIDENCE_INCOMPLETE`이면 근거 섹션에 서버 사유와
코드를 표시한다. 외부 논문이 있어도 등록된 출처·적용 조건을 통과하지 못한
경우 보류를 유지한다. 문헌 검토 실패와 근거 부족 상태도 구분한다.

## 통합 수정

원격 f838439 병합으로 요청 입력 폼 안에 기존 버전의 보고서·승인 JSX가
중복 삽입돼 빌드가 실패했다. 잘못 삽입된 부분을 제거하고 최신 검토 콘솔의
역할 확인·체크박스·보고서 해시·유효 시간 확인을 유지했다.

## 실행·확인

```powershell
# 저장소 루트에서 Python 환경을 준비한 뒤
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1

# 별도 프런트 터미널
cd frontend
npm ci
npm run build
npm run check:evidence
npm run dev
```

`check:evidence`는 합성 테스트 자료로 세 수집 경로, 수집 방식 누락,
서버 보류 사유, 링크·인용·조건, 위험한 URL, 빈 상태를 렌더링 검사한다.
실제 검색·LLM 정확도나 브라우저 상호작용을 검증한 것은 아니다.

로컬 기본 토큰과 초기 합성 상태에서 실행 흐름·DB를 확인하려면:

```powershell
python scripts/check_local_runtime.py
# 백엔드 종료 후 같은 data/ironman.sqlite3로 재시작
python scripts/check_local_runtime.py --after-restart
```

이 명령은 합성 시연 요청 두 개와 가상 명령 적용 기록을 생성한다. 실제 이메일을
발송하지 않는다. 사용자 데이터를 삭제하거나 초기화하지 않는다. 기존 가상 상태가
초기 상태와 다르면 60%/80% 예상 결과가 달라질 수 있다.

DB는 기본 `data/ironman.sqlite3`이며 Git에 포함하지 않는다. `/health`의 sqlite
표시만으로 영속성을 주장하지 않는다. API로 저장·재조회하고 SQLite 무결성 검사와
재시작 후 보고서 해시·감사 기록 유지까지 확인해야 한다.
