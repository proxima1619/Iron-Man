# Iron Man — 설비 변경 요청 안전 관문

AI의 설비 변경 요청을 가상 환경에서 검토하고, 담당자가 승인한 명령만 적용하는 프로젝트의 **4인 팀 개발 골격**입니다.

> 현재는 로컬 데모입니다. 실제 PLC·설비가 연결되어 있지 않습니다. 시뮬레이션 숫자와 근거 검토는 **고정 모의 값**이고, 실제 물리 모델·문헌 검색·LLM은 아직 없습니다. 모의 결과의 승인은 가상 설비에만 적용됩니다.

## 담당별 시작점

| 담당 | 폴더 | 다음 구현 |
|---|---|---|
| 1번 | `backend/gateway`, `backend/main.py` | DB 영속성, 실제 인증, 비동기 평가, 통합·배포 |
| 2번 | `backend/simulator` | 물리 모델, 시계열·범위 검증, 상태·어댑터 |
| 3번 | `backend/evidence` | 실제 출처 검색, 구조화 LLM 검토, 적용 조건·근거 부족 |
| 4번 | `frontend/src` | 그래프, 출처 확인 UI, 보고서 표현, 발표·영상 |

공통 계약 v1.0은 [팀 연동 계약](contracts/README.md)에 정리되어 있습니다. JSON 예시·상태별 처리·생성 명령을 먼저 확인하세요. Python 원본은 `backend/contracts.py`, 프런트 자동 생성 타입은 `frontend/src/api.generated.ts`입니다. 변경 시 네 담당의 입력·출력을 함께 확인하세요.

## 현재 동작하는 흐름

```text
React → FastAPI → 요청·데모 정책 검사
                 → 모의 근거 검토 → 반례 시험 추가
                 → 모의 시뮬레이터 → 차단 또는 승인 대기
                 → 서버의 승인자 확인
                 → 명령·보고서·상태·버전·만료 재확인
                 → 가상 어댑터 적용·기록
```

- 서버: 요청 생성·평가·승인·거절·가상 실행, 상태 변경 시 재검증, 중복 실행 방지
- 화면: 요청 입력, 조건별 비교 표, 모의 근거 카드, 승인·실행, 처리 기록
- 검증: API 통합 테스트, 프런트 타입 검사·빌드, GitHub Actions 구성
- 저장: **프로세스 메모리**. 서버 재시작 시 요청·승인·기록이 사라집니다. 단일 worker만 사용하세요.

## 실행

Python 3.11 이상, Node.js 22 이상을 권장합니다. 저장소 루트에서 시작합니다.

터미널 1 — 백엔드:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -c requirements-dev.lock.txt -e '.[dev]'
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

터미널 2 — 화면:

```bash
cd frontend
npm ci
npm run dev
```

- 화면: http://127.0.0.1:5173
- API 문서: http://127.0.0.1:8000/docs
- 상태 확인: http://127.0.0.1:8000/health

Vite 개발 서버의 `/api` 프록시가 백엔드로 연결합니다. 빌드된 정적 파일을 배포할 때는 별도 `/api` 리버스 프록시가 필요합니다. 외부 공개 배포는 아직 구성하지 않았습니다.

## 모의 데모 순서

1. 기본 `local-operator` 토큰으로 **60%** 요청 → 정상 모의 조건 통과, 효율 저하 모의 조건 차단.
2. **80%**로 새 요청 → 모의 승인 대기.
3. 토큰을 `local-approver`로 바꾸고 승인 → 가상 설비에 적용.
4. 다시 80% 새 요청을 검토·승인 → `데모: 부하 변경` → 적용 시 서버가 재검증 요구.

60·80% 기준과 온도 숫자는 **테스트 흐름을 위한 고정 fixture**이며 현실 안전 기준이 아닙니다. 수정은 새 요청으로 만들며 기존 승인을 재사용하지 않습니다.

`local-operator`, `local-approver`는 로컬 데모용 공개 토큰입니다. 운영 인증이 아닙니다. `.env.example`의 환경변수를 셸에서 export하면 변경할 수 있습니다. `.env` 자동 로딩은 하지 않습니다. 실서비스 인증·비밀 관리·사용자 식별은 1번의 후속 구현입니다.

## 확인 명령

```bash
# 저장소 루트, 가상환경 활성화 상태
pytest -q

# 프런트
cd frontend
npm run build
```

`.github/workflows/check.yml`은 push/PR 시 같은 검사를 수행하도록 구성되어 있습니다. CI 성공 여부는 GitHub 실행 결과에서 확인하세요.

## 구현 시 주의할 경계

- 2번은 계산, 3번은 근거, 4번은 표시, 1번은 판정·실행 권한을 담당합니다.
- 실제 모듈로 교체할 때 현재의 `mock=True` 계약과 데모 전용 승인 정책도 함께 바꾸어야 합니다. `unknown` 적용 조건을 현실 설비의 승인 근거로 사용하지 마세요.
- 계산·문서 오류는 보류, 실행 결과 불명은 추가 실행 금지로 처리합니다.
- 실행 중 네트워크 응답 유실의 재조정, DB 트랜잭션, 다중 프로세스 동시성은 후속 구현입니다.
- 감사 기록은 일반 메모리 목록입니다. 영구·변조 불가능 기록을 구현한 것이 아닙니다.
- 실제 데이터나 비밀키를 fixtures, Git, Codex 제출 기록에 넣지 마세요.
